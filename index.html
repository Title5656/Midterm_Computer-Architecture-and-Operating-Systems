3 บทบาทของ OS (กดเปิด)

1) Virtualization ของ physical resourcesทรัพยากรจริงมีจำกัด: CPU รันได้ไม่กี่คำสั่งในเวลาเดียว และ memory ต้องแบ่งกัน OS ทำให้ทรัพยากร ดูเหมือนมีไม่จำกัด เรียกเทคนิคนี้ว่า Virtualization บางครั้งเรียก OS ว่า virtual machine หรือ extended machine
CPU: OS สลับระหว่าง Program 1, 2, 3 แล้วสั่ง CPU รันทีละคำสั่ง คำถามคือสลับอย่างไร และใครได้รันก่อน
Memory: แต่ละโปรแกรมมี address space ของตัวเอง (virtual address เริ่มที่ 0x00000 เหมือนกัน) ถูกแมปไปยัง physical address ต่างกัน คำถามคือแมปอย่างไร จัดสรรอย่างไร และทำอย่างไรเมื่อ memory ไม่พอ
2) APIs (system calls / standard library)ให้ผู้ใช้และแอปสั่ง OS ได้ เช่น รันโปรแกรม เข้าถึงไฟล์ จัดสรร memory APIs เหล่านี้ ซ่อนความซับซ้อนของฮาร์ดแวร์ (ฮาร์ดแวร์เป็น “ugly interface” OS ทำให้เป็น “beautiful interface” ให้แอปใช้)
3) Resource managerโปรแกรมที่รันพร้อมกันต้องแบ่ง CPU time, memory space, disk และ I/O devices OS จัดสรรเพื่อให้มี efficiency และ fairness สูง

Process: โปรแกรมที่กำลังรัน

Process = a running program การรันโปรแกรมด้วยมือยากเพราะมีหลายขั้นตอนและใช้ข้อมูลมาก OS จึงทำ abstraction นี้ให้ ผู้ใช้รันหลายโปรแกรมได้โดยไม่ต้องสนใจว่า CPU ว่างหรือไม่

Machine state ที่ process ซ่อนไว้

Process ซ่อนรายละเอียดของ machine state คือ: memory (คำสั่งและข้อมูลอยู่ใน address space), registers (general purpose เช่น eax, ebx; program counter PC; stack pointer; frame pointer) และ I/O devices เช่น ไฟล์ที่เปิดอยู่

Misc Controlเช่น suspend / resume

ขั้นตอนสร้าง Process

  1. OS โหลด code และ static data จาก disk เข้า memory (code, data, heap, stack)
  2. OS เตรียม I/O เริ่มต้นของ Unix: standard input, standard output, standard error
  3. OS ตั้งคำสั่งแรก (เช่น main())
  4. OS ส่งต่อการควบคุม CPU ให้ process

Process States: ลองสลับสถานะเอง

  • Running CPU กำลังรันคำสั่งของ process
  • Ready พร้อมรัน แต่ OS ยังไม่เลือก
  • Blocked รอเหตุการณ์ ส่วนใหญ่คือ I/O ที่ยังไม่เสร็จ

ตัวอย่างสองโปรเซส (เลื่อนเวลา)

Process Control Block (PCB)

OS ต้องติดตามข้อมูลของแต่ละ process เช่น state เพื่อ schedule ให้ถูก จึงใช้ struct (ภาษา C) ต่อหนึ่ง process เรียกว่า PCB และมี Process Table แมป PID ไปที่ PCB (กดดูตัวอย่าง)

ตัวอย่าง PCB ใน xv6 (C)
struct proc {
  char *mem;            // Start of process memory
  uint sz;              // Size of process memory
  char *kstack;         // Bottom of kernel stack
  enum proc_state state;// Process state
  int pid;              // Process ID
  struct proc *parent;  // Parent process
  void *chan;           // If !zero, sleeping on chan
  int killed;           // If !zero, has been killed
  struct file *ofile[NOFILE]; // Open files
  struct inode *cwd;    // Current directory
  struct context context;     // Switch here to run process
  struct trapframe *tf; // Trap frame for current interrupt
};
// states: UNUSED, EMBRYO, SLEEPING, RUNNABLE, RUNNING, ZOMBIE
struct context { int eip, esp, ebx, ecx, edx, esi, edi, ebp; }; // registers ที่ต้องเซฟ

UNIX Process API: fork, wait, exec

โปรแกรม C พื้นฐาน

#include <stdio.h>
void main() {
    int x;                              // ตัวแปรในเครื่อง (อยู่ใน stack)
    x = 10;
    printf(" Hello World \n");
    printf(" value of x is %d\n", x);   // พิมพ์: value of x is 10
}   // คอมไพล์: gcc -o first first.c   รัน: ./first

fork(): สร้าง process ใหม่

  • process ที่เรียก fork() คือ parent process ที่ถูกสร้างคือ child
  • child เริ่มต้นเป็น สำเนาตรงตัว ของ parent แต่มี address space และ PCB เป็นของตัวเอง
  • PID คือชื่อ (ตัวระบุ) ของ process
  • fork() คืนค่า PID ของ child ให้ parent และคืน 0 ให้ child (ใช้แยกว่าใครคือใคร)
int pid = fork();        // บรรทัดนี้ถูกรัน 2 ครั้ง โดย 2 process
if (pid > 0) {           // parent: pid = PID ของ child
    printf(" I am a parent process with PID = %d of child process %d\n", getpid(), pid);
    wait(NULL);          // parent รอ child จบก่อน
    exit(0);
} else {                 // child: pid = 0
    printf(" I am a child process with PID = %d\n", getpid());
    printf(" My parent process with PID = %d\n", getppid());
    exit(0);
}

ลองคิด: fork หลายครั้งได้กี่ process?

ทุกครั้งที่ fork ทุก process ที่มีอยู่จะแตกเป็นสองเท่า ในตัวอย่างสไลด์: fork() หนึ่งครั้ง แล้ว for(i<2) fork() รวม 3 ครั้ง ผลคือ 2³ = 8 process ลองเลื่อนดู

จำนวนครั้งที่ fork:

wait(): ให้ process รอ process อื่น

มีประโยชน์เมื่อต้องการให้ parent รอ child เช่น ให้ child พิมพ์ก่อนเสมอ ถ้าไม่ใช้ wait() ลำดับการพิมพ์ของสอง process ไม่แน่นอน (ตัวอย่าง fork2.c ในสไลด์มีผลลัพธ์ปนกัน เพราะ child ที่ parent จบก่อนยังรันต่อ)

exec(): เปลี่ยน process ให้เป็นโปรแกรมอื่น

exec() ไม่สร้าง process ใหม่ มัน แปลง process ปัจจุบันให้เป็นโปรแกรมอื่น และถ้าสำเร็จจะ ไม่ return กลับมา (โค้ดหลัง exec จะไม่ถูกรัน)
pid = fork();
if (pid == 0) {                    // child
    execlp("/bin/ls", "/home", NULL); // child กลายเป็นโปรแกรม ls
    printf("Child process again\n");  // ไม่ถูกรัน ถ้า exec สำเร็จ
} else wait(NULL);                 // parent รอ child

มี 6 รูปแบบ: execl, execv, execlp, execvp, execle, execvpe (l = list ของ argument, v = vector argv, p = ค้นหาจาก PATH, e = ส่ง environment)

สรุปสั้น: fork = ทำสำเนา · exec = เปลี่ยนโปรแกรม · wait = รอลูกจบ

System Call และ Dual Mode

OS รัน process แบบ Limited Direct Execution: เริ่ม process แล้วปล่อยให้รันบน CPU โดยตรง (Direct Execution) แต่ OS และฮาร์ดแวร์ จำกัด ไม่ให้ user process เข้าถึงทรัพยากรระบบเองเพื่อความปลอดภัย แล้ว process จะขอใช้ I/O ได้อย่างไร?

Dual mode

User mode (mode bit = 1) เข้าถึงทรัพยากรได้จำกัด Kernel mode (mode bit = 0) OS ทำ privileged operations ได้

user process ขอทำงานพิเศษด้วย system call ตัวอย่าง: open, read, write, close, kill, signal, fork, wait, exec, getpid, link, unlink, mount, chdir, setuid, getuid, chown

library ห่อ system call เป็นฟังก์ชัน C ให้เรียกเหมือน procedure call ธรรมดา เช่น printf ไปเรียก write() ข้างใน

Trap คือสัญญาณซอฟต์แวร์ที่โปรแกรมผู้ใช้ตั้งใจสร้างเพื่อสลับ CPU จาก user mode ไป kernel mode ให้ OS ทำ system call ที่ป้องกันไว้

Trap table บอกฮาร์ดแวร์ว่า trap handler ของแต่ละเหตุการณ์ (system call, keyboard interrupt) อยู่ที่ไหน · Kernel stack เก็บข้อมูลของ caller ให้กลับได้ถูก · return-from-trap คือคำสั่งพิเศษกลับไป process (ลดสิทธิ์)

เดินดูทีละขั้น

ตัวอย่าง read(fd, nbytes, buffer)

โปรแกรม push พารามิเตอร์ (nbytes, &buffer, fd) → call read → library ใส่รหัส read ใน register → trap เข้า kernel → Dispatch → sys call handler → กลับ library → เพิ่ม SP (เก็บ stack) → โปรแกรมทำต่อ

Context Switching

OS จะได้ CPU คืนเมื่อ: process yield, ถูก block (รอ I/O), สร้าง child แล้ว wait, หรือถูก terminate แต่ถ้า process วนลูปไม่รู้จบล่ะ? ใช้ Timer Interrupt

Timer Interrupt: อุปกรณ์ timer ส่ง interrupt ทุกกี่ millisecond ตัว interrupt handler ใน OS จะรัน ทำให้ OS ได้ CPU คืนอย่างปลอดภัย ตอนบูต OS บอกฮาร์ดแวร์ว่าจะรันโค้ดไหนเมื่อ timer ขัดจังหวะ แล้วเริ่ม timer

Context switching คือรูทีนของ OS เมื่อสลับ process ที่รันอยู่ ขั้นตอนรวม: 1) เซฟ context (registers) ของ process ที่รัน 2) คืน context ของอีก process
