01 / พื้นฐาน

ภาพรวม: คอมพิวเตอร์ทำงานอย่างไร

มองคอมพิวเตอร์เป็นโรงงาน: CPU อ่านและทำตามคำสั่ง, register เป็นพื้นที่เล็กและเร็วใกล้ CPU, RAM เป็นพื้นที่ทำงาน ส่วน SSD/HDD เก็บข้อมูลระยะยาว และ I/O เป็นช่องทางติดต่ออุปกรณ์ เช่น จอ คีย์บอร์ด และดิสก์

Operating system (OS) คือผู้จัดการที่แบ่ง CPU และหน่วยความจำให้โปรแกรม พร้อมดูแลสิทธิ์และอุปกรณ์ ลำดับคร่าว ๆ คือ ผู้ใช้ → โปรแกรม → OS → hardware

Architecture กับ Organization

  • Architecture คือคุณสมบัติที่โปรแกรมเมอร์มองเห็น เช่น ชุดคำสั่ง (ISA), register และรูปแบบข้อมูล: เครื่องทำอะไรได้
  • Organization คือวิธีสร้างเครื่องให้ทำงานตาม architecture เช่น วงจร cache และ bus: เครื่องทำได้อย่างไร

วงจรคำสั่ง: Fetch → Decode → Execute

  1. Fetch ดึงคำสั่งจากหน่วยความจำ
  2. Decode แปลว่าคำสั่งให้ทำอะไร
  3. Execute ทำงานตามคำสั่ง
Registerหน้าที่
PCตำแหน่งคำสั่งที่จะดึงต่อไป
IRคำสั่งปัจจุบัน
MARaddress ของหน่วยความจำที่ต้องการติดต่อ
MBR / MDRข้อมูลที่อ่านจากหรือจะเขียนลงหน่วยความจำ

Von Neumann ใช้หน่วยความจำและทางส่งข้อมูลร่วมกันสำหรับคำสั่งกับข้อมูล ส่วน Harvard แยกส่วนคำสั่งกับข้อมูล ส่วน bus มี data bus ส่งข้อมูล, address bus ระบุตำแหน่ง และ control bus ส่งสัญญาณควบคุม

02 / พื้นฐานคำนวณ

เลขฐานและการแทนจำนวน ⭐

เลขฐานสองและฐานสิบหก

แต่ละหลักของเลขฐานสองมีค่าน้ำหนักเป็นกำลังของ 2 เช่น 101101₂ = 32 + 8 + 4 + 1 = 45₁₀

เลขฐานสิบหกหนึ่งหลักเท่ากับเลขฐานสอง 4 บิต: 1011 0010₂ = B2₁₆ โดย A = 10, B = 11 ไปจนถึง F = 15

จำนวนเต็ม n บิตค่าต่ำสุดค่าสูงสุด
Unsigned02n − 1
Signed two’s complement−2n−12n−1 − 1

ตัวอย่าง 8 บิต: unsigned คือ 0 ถึง 255; two’s complement คือ −128 ถึง 127

Two’s complement

วิธีหา −x: เขียน +x ให้ครบจำนวนบิต → กลับทุกบิต → บวก 1

+3       0000 0011
กลับบิต  1111 1100
บวก 1    1111 1101  = −3

ตัวอย่าง 5 − 3 คิดเป็น 5 + (−3) ใน 8 บิต:

   0000 0101     +5
 + 1111 1101     −3
 -----------
 1 0000 0010

เก็บเพียง 8 บิต ตัด carry ที่เกินออก ได้ 0000 0010 = 2 ถ้าจะอ่านเลขติดลบกลับเป็นฐานสิบ ให้กลับบิต บวก 1 เพื่อหาขนาด แล้วใส่เครื่องหมายลบ

Overflow: บวกเลข signed เครื่องหมายเดียวกันแล้วผลเปลี่ยนเครื่องหมาย แสดงว่า overflow; carry ที่หลุดออกเพียงอย่างเดียวไม่ใช่เกณฑ์ตัดสิน signed overflow

Sign-magnitude

บิตซ้ายสุดเป็นเครื่องหมาย 0 = บวก และ 1 = ลบ ส่วนที่เหลือเป็นขนาด เช่น +3 = 0000 0011 และ −3 = 1000 0011 แบบ 8 บิต ดูให้ชัดว่าโจทย์กำหนด sign-magnitude หรือ two’s complement เพราะบิตเดียวกันอาจมีค่าต่างกัน

บวกเลขที่เครื่องหมายต่างกัน: ลบขนาดแล้วใช้เครื่องหมายของจำนวนที่มีขนาดมากกว่า เช่น +5 + (−3) = +2 สไลด์มีใบงานฝึกบวกและลบแบบ 16 บิต

IEEE 754 floating point

Single precision มี 32 บิต: sign 1 บิต | exponent 8 บิต | fraction 23 บิต สำหรับเลขปกติ:

ค่า = (−1)sign × 1.fraction × 2exponent − 127

ตัวอย่าง 6.5 = 110.1₂ = 1.101 × 2² ดังนั้น sign = 0, exponent = 2 + 127 = 129 = 10000001₂ และ fraction = 10100000000000000000000

Exponent ที่เป็น 0 หรือ 255 เป็นกรณีพิเศษ ไม่ใช้สูตรเลขปกติข้างต้นตรง ๆ

03 / คำสั่งและความเร็ว

RISC-V และประสิทธิภาพ CPU ⭐

อ่านคำสั่ง RISC-V

คำสั่งคำนวณเขียน ปลายทางก่อน; x0 มีค่า 0 เสมอ

add  x5, x6, x7     # x5 = x6 + x7
sub  x5, x6, x7     # x5 = x6 - x7
addi x5, x6, 10     # x5 = x6 + 10
lw   x5, 8(x6)      # โหลด word จาก address x6 + 8
sw   x5, 12(x6)     # เก็บ word ที่ address x6 + 12
beq  x5, x6, equal  # กระโดดถ้า x5 == x6
bne  x5, x6, differ # กระโดดถ้า x5 != x6
blt  x5, x6, less   # กระโดดถ้า x5 < x6 แบบ signed

lw/sw ใช้ word 4 bytes; ld/sd ใช้ doubleword 8 bytes และ offset เป็น byte หาก x10 เป็น address เริ่มต้นของ array ที่สมาชิกละ 8 bytes, ld x5, 24(x10) โหลด A[3] เพราะ 3 × 8 = 24

jal กระโดดพร้อมเก็บที่อยู่สำหรับกลับ; jalr กระโดดผ่าน address ใน register ใช้กลับจากฟังก์ชันได้

CPU time และ speedup

CPU time = instruction count × CPI ÷ clock rate

จำนวนคำสั่ง 2 × 10⁹, CPI 1.5 และ clock 3 GHz: (2 × 10⁹ × 1.5) ÷ (3 × 10⁹) = 1 วินาที

Speedup = เวลาเดิม ÷ เวลาใหม่

เดิม 10 วินาที ใหม่ 5 วินาที → speedup 2 เท่า Clock สูงกว่าไม่ได้รับประกันว่าเร็วกว่าเสมอ เพราะจำนวนคำสั่งและ CPI อาจต่างกัน

04 / หน่วยความจำ

Memory และ Cache ⭐

โดยทั่วไปเรียงจากเร็ว เล็ก และแพงต่อ byte ไปช้า ใหญ่ และถูกกว่า: register → cache → RAM → SSD/HDD

SRAM มักใช้ทำ cache และไม่ต้อง refresh; DRAM มักใช้เป็น RAM และต้อง refresh. Hit = พบข้อมูลใน cache; miss = ไม่พบและต้องไปหาระดับถัดไป

  • Temporal locality: ใช้ข้อมูลเดิมซ้ำในเวลาใกล้กัน เช่น ตัวแปรใน loop
  • Spatial locality: ใช้ข้อมูลที่อยู่ใกล้กัน เช่น อ่าน array ทีละตัว

Average Memory Access Time

AMAT = hit time + (miss rate × miss penalty)

Hit time 1 ns, miss rate 5% และ miss penalty 20 ns → 1 + (0.05 × 20) = 2 ns ใช้หน่วยให้ตรงกัน และ miss penalty ในสูตรนี้หมายถึงเวลาเพิ่มเติมเมื่อ miss

Direct-mapped cache

Offset เลือก byte ใน block; index เลือก cache line; tag ตรวจว่า line เก็บ block ที่ต้องการจริงหรือไม่

ตัวอย่าง address 32 บิต, cache 4 KiB, block 16 bytes: มี 4096 ÷ 16 = 256 lines; offset = log₂16 = 4 บิต; index = log₂256 = 8 บิต; tag = 32 − 8 − 4 = 20 บิต

| Tag 20 บิต | Index 8 บิต | Offset 4 บิต |
block number = floor(byte address / block size)
index        = block number mod จำนวน lines
tag          = floor(block number / จำนวน lines)

เช่น address 1200, block 16 bytes, 64 lines → block 75, index 11, tag 1 และ offset 0

ชนิดและนโยบายเขียน

  • Direct-mapped: block หนึ่งไปได้เพียง line เดียว
  • Fully associative: block ไปได้ทุก line
  • n-way set associative: block ไปได้หลาย line ภายใน set; จำนวน sets = lines ÷ n
  • Write-through: เขียนทั้ง cache และ memory
  • Write-back: เขียน cache ก่อน แล้วเขียนกลับ memory เมื่อจำเป็น
05 / สายการผลิตคำสั่ง

Pipeline และ Hazard ⭐

Pipeline ซ้อนขั้นตอนของหลายคำสั่ง เพิ่ม throughput หรือจำนวนคำสั่งที่เสร็จต่อหน่วยเวลา แต่ไม่รับประกันว่าเวลาของคำสั่งเดียวจะลดลง

IF → ID → EX → MEM → WB

IF ดึงคำสั่ง · ID แปลคำสั่งและอ่าน register · EX คำนวณ · MEM เข้าถึง memory เมื่อจำเป็น · WB เขียนผลกลับ register เมื่อจำเป็น

ไม่มี stall: จำนวน cycles = N + k − 1

สำหรับ N คำสั่งและ k ขั้น เช่น 10 คำสั่งใน pipeline 5 ขั้น ใช้ 10 + 5 − 1 = 14 cycles

Hazardเหตุแนวทางจัดการ
Structuralแย่ง hardware เดียวกันเพิ่มหรือแยก resource
Dataคำสั่งใหม่รอผลคำสั่งก่อนforwarding หรือ stall
Controlยังไม่รู้ทางไปหลัง branchpredict, stall หรือ flush
ld  x1, 0(x2)
add x3, x1, x4

ใน pipeline 5 ขั้นตามแบบสไลด์ กรณี load-use ติดกันนี้ต้องมี 1 stall แม้มี forwarding เพราะข้อมูลยังมาไม่ทัน

06 / อุปกรณ์และการประมวลผล

I/O, Storage และ Parallel

วิธีทำ I/O

วิธีการทำงาน
Programmed I/O / pollingCPU คอยตรวจอุปกรณ์และจัดการโอนข้อมูลเอง
Interrupt-driven I/OCPU ไปทำงานอื่นได้ แล้วอุปกรณ์ส่ง interrupt มาเรียก
DMACPU ตั้งค่าการโอน; DMA controller โอนระหว่างอุปกรณ์กับ RAM และแจ้งเมื่อเสร็จ

DMA ยังต้องให้ CPU ตั้งค่าและจัดการผล Memory-mapped I/O ใช้ address space และคำสั่งอ่านเขียน memory ติดต่ออุปกรณ์ ส่วน isolated I/O ใช้พื้นที่ address และคำสั่ง I/O แยกต่างหาก

HDD, SSD และ RAID

เวลาเข้าถึง HDD ≈ seek + rotational delay + transfer

Seek = หัวอ่านเคลื่อนไป track; rotational delay = รอ sector หมุนมาถึง; transfer = อ่านหรือเขียนข้อมูล รวม controller หรือ queue delay เพิ่มถ้าโจทย์ให้มา

ที่ 7200 RPM หนึ่งรอบใช้ 60/7200 วินาที = 8.33 ms และรอเฉลี่ยครึ่งรอบ = 4.17 ms. SSD ไม่มีจานหมุนและใช้ wear leveling เพื่อกระจายการเขียน/ลบ

  • RAID 0: กระจายข้อมูลเพื่อประสิทธิภาพ แต่ไม่มี redundancy
  • RAID 1: ทำสำเนาแบบ mirror
  • RAID 5: distributed parity ทนดิสก์เสียได้ 1 ลูก; ความจุใช้ได้ประมาณ (n−1) ลูก
  • RAID 6: double parity ทนดิสก์เสียได้ 2 ลูก; ความจุใช้ได้ประมาณ (n−2) ลูก

สูตรความจุข้างต้นสมมติว่าดิสก์มีขนาดเท่ากัน

Parallel processing

  • SISD: หนึ่งชุดคำสั่งกับหนึ่งชุดข้อมูล
  • SIMD: หนึ่งชุดคำสั่งกับข้อมูลหลายชุด เช่น vector operations
  • MIMD: หลายชุดคำสั่งกับข้อมูลหลายชุด เช่น multicore
  • GPU: เหมาะกับงานที่ทำแบบเดียวกันกับข้อมูลจำนวนมาก
  • Shared memory: ใช้พื้นที่หน่วยความจำร่วมกัน ต้องระวังการเข้าถึงพร้อมกันและใช้ synchronization
  • Message passing: แต่ละเครื่องมี memory ของตนและส่งข้อความหากัน

งานขนานไม่ได้เร็วขึ้นตามจำนวน processor เสมอ เพราะมีส่วนที่ต้องทำตามลำดับและต้นทุนการสื่อสาร

07 / ระบบปฏิบัติการ

Operating Systems และ Process

OS จัดสรร CPU, memory และอุปกรณ์; ให้บริการผ่าน system calls; ควบคุมสิทธิ์และป้องกันโปรแกรมรบกวนกัน รวมทั้งสลับ CPU ให้หลายโปรแกรมดูเหมือนทำงานพร้อมกัน

Program กับ Process

Program คือชุดคำสั่งที่เก็บอยู่ ส่วน process คือโปรแกรมที่กำลังทำงานพร้อมสถานะและทรัพยากร มี code, data, heap, stack และสถานะ CPU เช่น PC และ registers. PCB เก็บข้อมูลที่ OS ใช้จัดการ process เช่น state, PC และ registers

สถานะ process

  • Ready: พร้อมทำงานแต่รอ CPU
  • Running: กำลังใช้ CPU
  • Blocked / Waiting: รอเหตุการณ์ เช่น I/O

Ready → Running เมื่อได้ CPU; Running → Ready เมื่อหมดเวลาหรือถูกแย่ง CPU; Running → Blocked เมื่อขอ I/O; Blocked → Ready เมื่อ I/O เสร็จ จากนั้นจึงรอ scheduler เลือกอีกครั้ง

Context switch คือ OS เก็บสถานะของ process เดิมและคืนสถานะของ process ใหม่ เพื่อให้ CPU สลับงานได้ โดยมี overhead

System calls

  • fork() สร้าง child process; parent ได้ PID ของลูก ส่วน child ได้ 0
  • exec() เมื่อสำเร็จ นำโปรแกรมใหม่มาแทนโปรแกรมเดิมใน process เดิม ไม่ได้สร้าง process ใหม่
  • wait() ให้ parent รอ child

ถ้าไม่มีการกำหนดลำดับด้วย synchronization หรือ wait อย่าเดาว่า parent หรือ child จะพิมพ์ก่อน User mode จำกัดสิทธิ์ ส่วน kernel mode ให้ OS ทำงานที่มีสิทธิ์สูงกว่า; system call เปลี่ยนเข้าสู่ kernel เพื่อให้ OS จัดการ

08 / โจทย์คำนวณ

CPU Scheduling ⭐

Scheduler เลือก process ใน ready queue ที่จะได้ CPU ต่อไป โจทย์ควรเริ่มด้วยการวาด Gantt chart แล้วหาค่าเวลาของแต่ละ process

สูตรจำเป็น

ให้ A = arrival time, B = CPU burst, C = completion time และ S = เวลาที่ได้ CPU ครั้งแรก

Turnaround = C − A
Response = S − A
Waiting = เวลารวมที่รอใน ready queue

ถ้ามี CPU burst อย่างเดียว ไม่มี I/O หรือ overhead: waiting = turnaround − burst. หากมี I/O ต้องนับเวลาที่อยู่ใน ready queue แทน

เปรียบเทียบ FCFS, SJF และ Round Robin

ตัวอย่างทุก process มาถึงเวลา 0 และลำดับเริ่มต้น P1, P2, P3: burst ของ P1 = 8, P2 = 4, P3 = 2

FCFS: ใครมาก่อนรันก่อน

เวลา  0         8       12    14
      |--- P1 ---|-- P2 --| P3 |

Waiting ของ P1 = 0, P2 = 8, P3 = 12 → เฉลี่ย (0 + 8 + 12) ÷ 3 = 6.67

SJF: งานสั้นที่สุดก่อน

เวลา  0    2       6          14
      | P3 |-- P2 --|--- P1 ---|

Waiting ของ P3 = 0, P2 = 2, P1 = 6 → เฉลี่ย (0 + 2 + 6) ÷ 3 = 2.67 หาก arrival ต่างกัน เลือกเฉพาะงานที่มาถึงแล้ว

Round Robin: quantum = 2

เวลา  0   2   4   6   8   10  12  14
      |P1 |P2 |P3 |P1 |P2 |P1 |P1 |

P3 เสร็จเวลา 6 → รอ 6 − 2 = 4; P2 เสร็จเวลา 10 → รอ 10 − 4 = 6; P1 เสร็จเวลา 14 → รอ 14 − 8 = 6. Waiting เฉลี่ย = (4 + 6 + 6) ÷ 3 = 5.33

วิธีหลักการและข้อควรจำ
FCFS / FIFOมาก่อนรันก่อน งานสั้นอาจรอหลังงานยาว เรียก convoy effect
SJFเลือก burst สั้นที่สุดในงานที่พร้อม เป็นแบบ non-preemptive
STCF / SRTFเลือกงานที่เหลือเวลาน้อยที่สุด เป็นแบบ preemptive
Priorityเลือก priority สูงก่อน งาน priority ต่ำอาจเกิด starvation
Round Robinสลับตาม quantum; quantum เล็กมากเพิ่ม overhead
MLFQหลายคิวและ priority งานใช้ CPU มากอาจถูกลดระดับ มี boost ลด starvation

Preemptive คือ OS แย่ง CPU ก่อนงานเสร็จได้; non-preemptive คือโดยหลักรันต่อจนเสร็จหรือยอมปล่อย CPU

ตัวอย่าง Round Robin บางหน้าในสไลด์มีข้อความระบุ burst ไม่สอดคล้องกับแผนภาพ ให้ยึดการวาดเส้นเวลาและคำนวณจากตัวเลขโจทย์
09 / ลองทำด้วยตัวเอง

ทดสอบตัวเอง

ลองตอบก่อน แล้วกดเปิดเฉลยทีละข้อ

01 · 1010₂ เท่ากับเท่าไรในฐานสิบ?

10 เพราะ 8 + 2 = 10

02 · −5 ใน two’s complement แบบ 8 บิตคืออะไร?

1111 1011 เริ่มจาก 0000 0101 กลับบิต แล้วบวก 1

03 · Signed two’s complement 8 บิตมีช่วงค่าเท่าไร?

−128 ถึง 127

04 · lw x5, 8(x6) ทำอะไร?

อ่าน word 4 bytes จาก memory ที่ address x6 + 8 เข้า x5

05 · CPU ทำงาน 1 พันล้านคำสั่ง, CPI 2, clock 2 GHz ใช้เวลากี่วินาที?

1 วินาที จาก instruction count × CPI ÷ clock rate

06 · Hit time 2 ns, miss rate 10%, miss penalty 30 ns: AMAT เท่าไร?

2 + 0.1 × 30 = 5 ns

07 · Pipeline 5 ขั้น ทำ 20 คำสั่งโดยไม่มี stall ใช้กี่ cycles?

20 + 5 − 1 = 24 cycles

08 · Process รอ I/O อยู่สถานะใด? เมื่อ I/O เสร็จไปสถานะใด?

Blocked → Ready แล้วรอ scheduler เลือก

09 · fork() กับ exec() ต่างกันอย่างไร?

fork() สร้าง process ลูก; exec() แทนโปรแกรมใน process เดิม

10 · มาถึงเวลา 2 เริ่มใช้ CPU เวลา 5 เสร็จเวลา 12 ใช้ CPU 6 หน่วย ไม่มี I/O: turnaround, response และ waiting เท่าไร?

Turnaround = 12 − 2 = 10; response = 5 − 2 = 3; waiting = 10 − 6 = 4

11 · RAID 0 กับ RAID 1 ต่างกันอย่างไร?

RAID 0 กระจายข้อมูลและไม่มี redundancy; RAID 1 ทำสำเนาแบบ mirror

12 · คำสั่งหนึ่งต้องรอผลของคำสั่งก่อนหน้าเป็น hazard ชนิดใด?

Data hazard

ทบทวนครั้งสุดท้าย

ชีทจำก่อนเข้าห้องสอบ

CPU time       = instruction count × CPI / clock rate
Speedup        = เวลาเดิม / เวลาใหม่
AMAT           = hit time + miss rate × miss penalty
Pipeline       = N + k − 1 cycles เมื่อไม่มี stall
Turnaround     = completion − arrival
Response       = first start − arrival
Waiting        = turnaround − burst เฉพาะกรณีไม่มี I/O/overhead

2's complement = กลับบิต + 1
Cache address  = tag | index | offset
Pipeline       = IF → ID → EX → MEM → WB
Process        = Ready → Running → Blocked → Ready

ถ้าติดข้อคำนวณ ให้เขียนสูตร ใส่หน่วย และวาดเส้นเวลาหรือตารางก่อน จะช่วยให้ตรวจความผิดพลาดได้ง่ายขึ้น
